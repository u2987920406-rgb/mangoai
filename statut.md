*Précédent : 2026-06-20 — **Cache Vite de l'aperçu corrigé (bug d'intégration #2 du run) — le dernier des 3 bugs ouverts** : l'aperçu (`preview.ts`) a un fast-path qui RÉUTILISE le process Vite déjà lancé tant que le `projectDir` est le même et que le serveur répond. Quand un projet est régénéré in-place avec un AUTRE framework (Svelte→Vue), le dossier ne change pas mais le process Vite garde l'ancienne config (plugin Svelte) en mémoire → aperçu live périmé alors que le build neuf est vert. Correctif ciblé : `configFingerprint(projectDir)` (hash SHA-1 de `vite.config.{js,ts,mjs}` + `package.json`, pur/testable) stocké dans `current` au démarrage ; le fast-path n'est pris que si l'empreinte est INCHANGÉE (sinon `stopPreview` + relance d'un process neuf à config fraîche). En plus, sur changement in-place détecté, `purgeViteCache` supprime `node_modules/.vite` (le pré-bundle de deps optimisé pour l'ancien framework, sinon servi périmé même par un process neuf). Deux niveaux de cache traités : config en mémoire (empreinte) + deps sur disque (purge). **`test-preview.ts` 5/5 (empreinte idempotente, Svelte≠Vue, changement in-place détecté, ajout de dépendance détecté, dossier sans config → empreinte définie), `tsc` serveur 0 ; UI non touchée.** **🎉 Les 3 bugs d'intégration ouverts du run de validation 2026-06-20 sont désormais tous corrigés** (#4 gate backend, #3 latence audit, #2 cache Vite).***
