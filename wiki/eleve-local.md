# Élève & boucle d'apprentissage

> Le 4ᵉ cerveau de MangoOS : le modèle qui traite la routine, avec **escalade vers Claude** sur échec objectif. Livré au **Jalon D** (2026-06-13). Rend MangoOS model-agnostic. **Élève actif depuis 2026-06-22 : GLM-5.2 via Ollama Cloud** (gros modèle hébergé, clé API) ; l'Élève **local** Gemma 4 12B ($0, Ollama) reste le **repli commenté** dans `.env`.

## Rôle

Faire tourner les tours de génération à $0 quand c'est possible, Claude restant l'escalade + le **scribe d'axiomes**. L'Élève répond dans le contrat `<mangoos>` (voir [[coque-rigide]]), MangoOS exécute et juge objectivement (`vite build`), escalade après N échecs.

## Détails clés

- **Modèle actif** : `glm-5.2:cloud` via **Ollama Cloud** (provider `openai`, endpoint OpenAI-compat `https://ollama.com/v1`, clé API Bearer) depuis 2026-06-22. **Repli local** : `gemma4:12b` via Ollama (`http://localhost:11434`, `ollama serve`, 1er appel ~60 s) — décommenter `ELEVE_MODEL=gemma4:12b` + retirer les 3 lignes provider dans `.env`. Qwen entièrement retiré le 2026-06-17.
- **Profils par famille** (`models/`) : `resolveProfile(model)` route sur la partition du modèle (system prompt + axiomes + caps + routage d'escalade). `gemma.ts` = WRITE-ONLY (petit modèle qui rate le find/replace) ; **`glm.ts` (2026-06-22)** = WRITE **+ EDIT** + caps généreuses `{axiomCap:10, fileBudget:24000, fileMax:6000, maxAttempts:3}`, axiomes `.axioms.md`/`.axioms.glm.md` ; `uxui.ts`/`layout.ts` = spécialistes #145 ; `generic.ts` = repli non-régression. Un modèle non reconnu → GENERIC.
- **Boucle de relais** (`eleve.ts` → `runRelay`) : prompt d'entrée STRICT obligatoire (sinon l'Élève dérape), `executeContract` applique, `inspectProject` juge sur **signaux objectifs** (`build-failed`/`timeout`/`no-deps`…), escalade Claude qui corrige + écrit un axiome. Cerveaux `askEleve`/`escalate` **injectables** (`defaultRelayDeps`) → testable sans réseau.
- **Branchement chat** : 4ᵉ cerveau `model === "eleve"` (sélecteur UI) → `/api/chat` route vers `runRelay` (sinon `runAgent`/Claude inchangé). Métriques `resolvedBy`/`attempts`/`projectType`.
- **L'Élève sait aussi DISCUTER & PLANIFIER (2026-06-22)** : `runRelay` est un moteur de **build** → pour que « rester sur l'Élève » vaille aux 3 actions de la chatbox (Construire/Planifier/Discuter), une branche `if (model==="eleve" && mode==="discuss")` court-circuite le build et appelle **`chatEleve`** (`eleve.ts`, enveloppe `askEleveDispatch`) : réponse **texte, zéro build**, posture `DISCUSS_RULES` (`assembleSystemPrompt`) + fil récent (`loadHistory`) repassé en contexte (l'Élève n'a pas de session SDK comme Claude). Construire = build (runRelay) ; Planifier & Discuter = conversationnel. **Limite** : le build Élève reste **stateless** (ne lit pas l'historique) → un plan « Discuté » n'informe pas automatiquement un build GLM ultérieur.
- **Sélecteur de modèle PAR BOUTON (UI, `Chat.jsx`)** : chaque action (Construire/Planifier/Discuter) a son modèle configurable (GLM-5.2/Sonnet/Opus/Haiku) via un menu déroulant, **mémorisé** (localStorage `mangoos.actionModels`), **défaut GLM-5.2 partout**. Fini la bascule Claude en dur. Le planificateur est détecté par l'**action active**, plus par `model==="opus"`.
- **Élève turbo** (`ELEVE_PROVIDER`) : `ollama` (local $0) ou `openai` (endpoint OpenAI-compat — Ollama Cloud, DeepSeek, Together…). `askEleveOpenAI` fait un POST `completionsUrl(ELEVE_API_URL)` + `Authorization: Bearer ELEVE_API_KEY`, **même contrat d'E/S** que la version Ollama → boucle de relais inchangée. **C'est la voie de l'Élève GLM-5.2 cloud actuel.** ⚠ Provider **global** (affecte aussi les agents spécialisés uxui/layout) ; ⚠ tour `openai` **compté coût 0** dans les métriques/traces → coût cloud réel non tracé (futur chantier, cf. [[traces]]/#134) ; code/prompts partent chez le tiers (Ollama Cloud ici).
- **Discipline d'ablation** : après chaque axiome de code né d'une escalade, `npx tsx src/audit-scan.ts --ablate` (suite AVEC vs SANS le dernier axiome) → si l'axiome dégrade l'Élève, l'amender/retirer. Verdict sur le **rendement réel** (`audit-verify.ts`), pas la compilation seule.

- **Élève AGENTIQUE — des OUTILS (#146, Phase 1, 2026-06-22)** : le grand pas vers « Mango = Claude ». L'Élève ne savait qu'écrire via le contrat `<mangoos>` ; maintenant un **cerveau fort (GLM)** peut piloter une **boucle agentique à outils** (function-calling) — lire/chercher/vérifier comme Claude. Infra : `eleve-tools.ts` `buildEleveTools(projectDir)` = 4 `KernelTool` lecture seule (`read_file`/`list_files`/`search_code`/`check_build`, garde-fous `executor.ts`) ; `eleve.ts` `askEleveAgentic` = la boucle (envoie `tools` via `toOpenAITools` du Kernel #108, lit `tool_calls`, invoque, itère, bornée). **Gaté par profil** : flag `agentic` (GLM seul ; petits modèles gardent le contrat — frontière #135). **Phase 1** = outils LECTURE SEULE + **passe d'exploration dans `runRelay`** (GLM explore avant de coder, résumé injecté ; additif, jamais bloquant, opt-out `ELEVE_AGENTIC=off`). Prouvé live : GLM explore et raisonne juste.
- **Élève AGENTIQUE — POSSÉDER LE MOTEUR (#146, Phase 2, 2026-06-22)** : le grand pas. Cadre fixé par Raf : MangoOS = **toute la coquille de Claude sans le cerveau** (interchangeable). Verdict d'exploration : la coquille est **déjà neutre au modèle à ~70-95 %** (cf. [[kernel]] Brain Adapter, 7 providers, profils, features `<FEATURE>_PROVIDER`) ; le **seul** point « en forme de Claude » restant = la **boucle agentique** (SDK Anthropic `query()`). Décision : **posséder ce moteur**, Claude en filet d'escalade, viser le modèle le plus complet (jusqu'à délégation + multi-cerveaux) mais **étape par étape**. **Livré (A/B/C)** : **(A)** outils d'ACTION `eleve-action-tools.ts` (`write_file`/`edit_file`/`run_command`/`finish`) adossés aux primitives sûres d'[[coque-rigide]] `executor.ts` (`applyWrite`/`applyEdit`/`applyRun` → délèguent à `executeContract` → zéro duplication de sécurité). **(B)** runtime MAISON `eleve-runtime.ts` `buildAgentic` — module **pur** (transport `post` injecté, testable sans réseau) : boucle auto-corrective bornée (terminaison `finish`, **anti-répétition**, **compaction de contexte = pilier** qui borne contexte ET coût cloud, traces OTel) ; `elevePost` = transport OpenAI-compat factorisé. **(C)** bifurcation dans `runRelay` : pour un profil `agentic` + `ELEVE_PROVIDER=openai`, la tentative **DEVIENT la boucle outils** (au lieu du contrat `<mangoos>`), pilotée par le **prompt COMPLET** (`assembleSystemPrompt`, assemblé dans `index.ts`, passé via `RelayOptions.systemFull`) → **toute la coquille pilote le moteur, pas un prompt nu** ; escalade Claude **factorisée** (`finalizeEscalation`, INCHANGÉE) ; **réversible** (`ELEVE_AGENTIC=off` → contrat ; Gemma jamais concerné). **Principe gravé** : tout est pour **Mango**, rien pour GLM — le runtime ne connaît pas le cerveau (injecté) ; demain un modèle local hérite du moteur sans le toucher (c'est *exactement* ce que fait Claude Code avec Haiku/Sonnet/Opus). **Prouvé LIVE** : GLM-5.2 construit une feature React de bout en bout (write→edit→check_build→finish, 5 itérations, 122 s), build Vite vert, `resolvedBy:eleve`, **coût Claude $0, zéro escalade**. **Reste** : Phase D (délégation à des sous-agents — outil `delegate`, miroir de l'outil `Agent` de Claude), Phase E (multi-cerveaux par intention #135). Plan complet A→E dans le fichier de plan de session.
- **Élève AGENTIQUE — DÉLÉGATION (#146, Phase D, 2026-06-22)** : le maillon « appeler un agent » du schéma canonique. **Élégance** : un sous-agent = une instance bornée du MÊME `buildAgentic` ; `delegate` n'est qu'un OUTIL DE PLUS — son handler relance la boucle sur la sous-tâche, `buildAgentic` ignore tout de la délégation. `eleve-runtime.ts` `runAgenticTask(user, ctx)` (orchestrateur récursif, module PUR : `buildRegistry`/`buildUser` injectés → pas d'import d'eleve.ts) enregistre l'outil `delegate(subtask)` tant que `depth < maxDepth` ; `makeDelegateTool` borne par **profondeur** (`ELEVE_DELEGATE_MAX_DEPTH`=2) et **budget PARTAGÉ** de sous-agents (`ELEVE_DELEGATE_MAX_AGENTS`=4, objet par référence) ; traces OTel imbriquées (span par profondeur) ; sécurité inchangée (mêmes outils gardés `executor.ts`). `runRelay` (branche agentique) passe par `runAgenticTask`. `test-eleve-runtime` **21/21** (+8 : nominale, profondeur max, budget épuisé). **Prouvé LIVE** : GLM délègue 2 composants React à 2 sous-agents distincts (chacun write→check_build→finish à profondeur 1), puis intègre les deux dans App.jsx — 2 délégations réelles, build vert, $0, zéro Claude. C'est l'**orchestrateur fort + feuilles bornées** de #135. **Reste** : Phase E (multi-cerveaux par intention).
- **Anti-blocage & révision « apprendre, pas secourir » (#146, 2026-06-24)** : sur de grosses apps, GLM **sur-explore** (relit en boucle, n'appelle jamais `finish`) → build vert mais tâche incomplète. 1er correctif (commit `7aa19d9`) : garde **anti-relecture** (`READ_ONLY_TOOLS` déjà lus → court-circuités, on pousse à AGIR) + auto-escalade Claude sur blocage. **Raf recadre** : ne PAS courir vers Claude à la moindre erreur — il faut **apprendre** au cerveau (« classe Fable 5 »), pas le **secourir**. **Révision (4 points)** : (1) **plus de marge** — le seuil de sortie « bloqué » `maxCorrections` est DÉCOUPLÉ du `repeatLimit` par-clé (env `ELEVE_AGENTIC_MAX_CORRECTIONS`, défaut **8** au lieu de 3) ; (2) **GLM finit lui-même** — sur blocage+build vert, boucle d'**auto-relance** (`ELEVE_SELF_RELANCE_MAX`=2) avec un coup de pouce injecté (« arrête de lire, AGIS et termine »), $0, zéro Claude ; (3) **escalade Claude = OPT-IN** (`ELEVE_ESCALATE_ON_BLOCK=on` requis ; défaut OFF → on rend la main à Raf en `incomplete`) ; (4) **apprendre en amont** — `AGENTIC_TOOL_CONTRACT` durci (« ÉCONOMIE DE LECTURE : lis le minimum, ne relis jamais, va jusqu'au finish »). `test-eleve-runtime` **34/34** (#3c prouve la marge), `test-relay` **F4a/b/c** (défaut sans Claude · auto-relance qui RÉUSSIT · opt-in escalade). **PROUVÉ LIVE (2026-06-24, GLM réel sur `formation-toic`)** : tâche multi-fichiers → plafond 24 sans finish (build vert) → auto-relance 1/2 → finish en 5 itérations → résolu par l'Élève, coût 0, **zéro Claude** ; modif câblée sur 4 fichiers + `vite build` vert. **Philosophie gravée ET vérifiée : MangoOS apprend à son cerveau à finir, il ne le remplace pas.**
- **2 gardes anti-blocage de plus (#146, 2026-06-24)** : un usage réel (tâche démesurée = « 4 phases d'un coup ») révèle que GLM **sur-explore toujours** — ~12 `search_code` + lectures, **zéro écriture**, plafond — et que mes 3 gardes sont AVEUGLES à ce motif (elles ne voient que les lectures identiques / échecs consécutifs / appels identiques, pas « beaucoup de lectures DISTINCTES réussies sans écrire »). Pire, il **contourne** via `run_command Get-Content`. **(1) Anti-exploration-stérile** (`eleve-runtime.ts`) : compteur `readsSinceWrite` ; au seuil `ELEVE_EXPLORE_BEFORE_ACT_MAX`=6, REFUSE une lecture de plus + « ÉCRIS maintenant » ; une écriture/`delegate` remet à zéro. **(2) Anti-shell-lecture** (`eleve-action-tools.ts` `isShellReadCommand`) : `run_command` refuse `Get-Content/cat/type/ls/dir/Select-Object/findstr…` → renvoie vers read_file ; les builds passent. `test-eleve-runtime` **37/37**, `test-eleve-action-tools` **27/27**. **PROUVÉ LIVE (passe 1 bornée)** : Nav.jsx + Layout.jsx + App.jsx câblés, **6 itérations → finish du premier coup, 0 relance, 0 Claude, $0, vite build vert** (vs 24/plafond/rien avant). **2 leçons** : la garde anti-stérile manquait ; le périmètre compte (passe par passe > tout d'un coup).
- **Outil `add_dependency` — l'agent gère ses dépendances (#146, 2026-06-24)** : gap découvert en réel — GLM importe `lucide-react` dans 4 composants sans que la lib soit dans package.json/node_modules, et le moteur **interdit `npm install`** (FORBIDDEN_RUN) → imports non résolus, app cassée, « build vert » trompeur (lib transitoire jamais persistée). **Décision de Raf : install CURÉ.** `eleve-action-tools.ts` : `SAFE_DEPENDENCIES` (allowlist ~25 libs front sûres), `isAllowedDependency` (double garde : regex nom **+** allowlist → anti-injection), outil **`add_dependency(package)`** (npm install --save borné → persisté dans package.json, build reproductible ; hors liste → refus + « SVG inline » ; toujours dispo même cerveau faible). Contrat : « pour une lib externe, appelle d'abord add_dependency ; jamais d'import sans install ». `test-eleve-action-tools` **33/33**. App formation-toic débloquée (lucide installé+déclaré, build vert). **PROUVÉ LIVE (passe 4, GLM réel)** : `read → add_dependency('recharts') → edit import → edit LineChart → check_build → finish` (bon ordre : install AVANT import), 5 itérations, 0 Claude, $0 ; recharts persisté dans package.json, vite build vert. **Le maillon manquant : l'agent ne fait plus qu'écrire, il provisionne ses libs — validé en réel.**
- **Orchestration nocturne : formation TOEIC finie en guidant GLM (#146, 2026-06-24)** : Raf confie l'app entière à Claude-orchestrateur (« gère de haut, GLM fait le code, qu'il apprenne »). Leçons RÉELLES sur GLM : (1) **fort en RÉÉCRITURE complète** (restyle Quiz+Feedback+ProgressBar puis AudioPlayer+SessionResult en Mango Pastel, 2 tours nets) ; (2) **faible en micro-édit de gros fichier** (sur-explore ProgressPage, écrit des `_dump.js`-poubelle pour le lire, thrashe — les gardes du jour l'empêchent de boucler à l'infini) ; (3) **code à l'AVEUGLE** = cause-racine de ses incohérences (il avait laissé tout le flux interactif en thème sombre sans le savoir ; un build vert ne prouve rien sur l'apparence). Claude a été ses **yeux** (Sharingan/Playwright à chaque étape) + a fait le debug CSS subtil (reset Tailwind v4 non-layered, flex). 5 axiomes écrits dans `.axioms.md` (réinjectés dans ses futurs builds) : VISION-01, UIUX-11, ARCH-12, ARCH-13, BUILD-25. ⟶ prochain chantier [[project-sharingan-vision-eleve]] : lui donner la VISION pour qu'il se relise et s'auto-corrige.
- **Personas `builder`/`controleur` pour `delegate` (SOUV-B, 2026-07-12)** : jusque-là l'outil `delegate` (Phase D ci-dessus) relançait toujours la même boucle générique. Ajout de deux personas dédiés — miroir des sous-agents Claude — dans `eleve/contract.ts` (`ELEVE_BUILDER_PROMPT`/`ELEVE_CONTROLEUR_PROMPT`, traductions françaises des prompts Claude équivalents), résolus par `resolveDelegateCtx` (`relay-agentic.ts`) quand `agentType==="builder"|"controleur"`. Ferme un des 10 écarts de parité trouvés par l'audit [[audit-souverainete]] — détail dans [[sharingan-vision-eleve]] et [[mangoqa]].
- **Souveraineté de la boucle (2026-06-22)** : principe gravé par Raf — **en mode GLM/Élève, toute la boucle est GLM + Mango, jamais Claude**. Concrètement : (1) génération = GLM (runRelay / chatEleve) ; (2) chat d'accueil = GLM (`home-chat` route `eleve`→`chatEleve`) ; (3) **feedback 👍/👎 = traité PAR GLM** — `processFeedback(..., ask?)` accepte un cerveau d'extraction injectable, `feedback-routes.ts` passe `chatEleve` quand `model==="eleve"` (sinon `FEEDBACK_PROVIDER`/Claude). L'axiome appris va dans le `.axioms.md` global (cerveau de Mango). Claude ne reste que le **filet d'escalade** du builder. Un pouce sur une réponse GLM apprend à GLM/Mango, pas à Claude.
