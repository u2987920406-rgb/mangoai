Le modèle devait savoir **piloter une boucle agentique**. Un appel réel à Ollama Cloud, avec un
outil déclaré, a répondu un `tool_calls` correct :

```
POST https://ollama.com/v1/chat/completions
```

## 3. Le Maître (escalade) = `opus`

Trois défauts pointaient encore sur Sonnet, écrits avant Opus 5.5 :

| Emplacement | Avant | Après |
|---|---|---|
| `server/src/eleve/relay-config.ts:84` | `?? "sonnet"` | `?? "opus"` |
| `server/src/cron-scheduler.ts:29` | `'sonnet'` en dur | `cronMaitreModel()` → `'opus'`, surchargeable `CRON_MAITRE_MODEL` |
| `server/src/train-loop.ts:243` | `?? "sonnet"` | `?? "opus"`, surchargeable `TRAIN_ESCALATE_MODEL` |

Justification : l'escalade est l'acte le plus exigeant du harnais (réparer un build que l'Élève n'a pas
su passer, puis distiller un axiome) et il est **rare et borné** (`maxMaitreGate`, plafonds d'escalade,
disjoncteur cron). Le poste de quota est faible ; la contrepartie en justesse est la plus élevée du
système. Le chemin **cron** est celui sans humain pour rattraper — c'est là qu'un Maître juste vaut le
plus.

## 6. Un conflit réel rencontré, et tranché

`npm run typecheck` de MangoOS était **rouge** avant ce lot, sur une seule erreur de type :

```
src/llm/llm-transport.ts(116,28): error TS2345
  Type 'Promise<SDKControlInterruptResponse | undefined>' is not assignable to type 'Promise<void>'
```

Cause : le SDK 0.3.284 fait retourner un **objet** à `interrupt()`, là où le contrat local attendait
`Promise<void>`. C'était une conséquence directe de la mise à jour du SDK, pas un défaut du lot. Corrigé
au bon endroit (le paramètre accepte désormais `Promise<unknown>` — on n'utilise que l'effet de bord),
typecheck repassé à **0**.
